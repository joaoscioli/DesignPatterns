# Architecture Review Checklist

Use this checklist to review the project as a design and maintainability exercise.

## Pattern Fit

- Each pattern solves a visible change pressure.
- The example stays small enough for the pattern intent to remain obvious.
- The implementation avoids ceremony that does not improve readability.

## Code Review Quality

- Tests describe behavior and protect the reason the pattern exists.
- Names explain roles such as command, strategy, state, or specification.
- Trade-offs are documented alongside the implementation.

## Practical Use

- Examples connect to backend workflows and business rules.
- Anti-pattern notes explain when a simpler solution is better.
- Future patterns are chosen because they add interview value.

## Interview Defense

Be ready to explain the difference between knowing a pattern and knowing when
the pattern is too much for the problem.
