# Senior Demo Path

Use this repository to explain how patterns solve business pressure, not as a memorized catalog.

## 1. Start with the problem

Describe the pain first: branching logic, fragile changes, duplicated policies, or hard-to-test flows.

## 2. Show the refactoring

Walk through one pattern from before to after. Good examples are Strategy for pricing behavior, Specification for eligibility rules, and Chain of Responsibility for approval flows.

## 3. Explain the tradeoff

Senior reviewers expect nuance. Mention when a pattern is useful, when it adds accidental complexity, and which tests protect the behavior.

## 4. Connect to production code

Close by mapping each pattern to a real backend scenario: billing, authorization, notification routing, plan upgrades, or workflow orchestration.
