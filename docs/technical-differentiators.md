# Technical Differentiators

This file highlights what makes the project stronger than a generic pattern catalog.

## Differentiators

- Explains patterns through trade-offs instead of definitions alone.
- Connects design choices to change pressure and refactoring safety.
- Documents anti-patterns and situations where simpler code is better.
- Treats abstraction as a cost that must earn its place.

## Why It Matters

The project demonstrates design maturity: knowing a pattern is useful, but
knowing when not to use it is a stronger engineering signal.
