# Technical Storytelling Guide

Use this guide to present the project clearly in an interview.

## Story Arc

1. Start with the problem: requirements change, and code needs to absorb that
   change without becoming unclear.
2. Explain the selection rule: patterns are chosen only when they reduce real
   maintenance cost.
3. Defend simplicity: a pattern is not senior by itself; judgment is senior.
4. Close with tests: each example should prove the behavior that made the
   abstraction useful.

## Strong Closing

This project is designed to show that I understand both design patterns and the
discipline needed to avoid overengineering.
