# Demo Evaluation Rubric

Use this rubric to evaluate a technical walkthrough of this project.

| Area | Strong Signal | Weak Signal |
| --- | --- | --- |
| Pattern selection | Explains the change pressure behind each pattern. | Lists pattern names without context. |
| Simplicity | Shows when a simpler design is better. | Adds abstraction only to look advanced. |
| Testing | Uses tests to prove the pattern behavior. | Tests only construction or trivial getters. |
| Trade-offs | Compares maintainability gains and costs. | Treats patterns as universally positive. |

## Passing Bar

A strong demo shows judgment: the developer knows patterns, but also knows when
not to use them.
