# Implementation Readiness

This file defines what must be clear before adding the next code example.

## Ready When

- The change pressure for the example is explicit.
- The simple starting design is understandable.
- Tests can protect behavior before refactoring.
- The selected pattern has a clear advantage over simpler alternatives.
- The trade-off introduced by the pattern is documented.

## Not Ready If

- The pattern is chosen before the problem is visible.
- The example needs excessive setup to understand.
- The refactoring cannot be verified through tests.

## Review Focus

Implementation should begin with a small before-and-after example that proves
design judgment rather than pattern memorization.
