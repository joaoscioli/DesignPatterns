# Technical Review Map

Use this map to review the repository quickly without losing the technical story.

## Review Path

1. Start with `docs/technical-elevator-pitch.md` for the short positioning.
2. Read `docs/pattern-selection.md` to understand decision criteria.
3. Open `docs/technical-risks.md` for abstraction risks.
4. Check `docs/acceptance-criteria.md` for the next refactoring example.
5. Finish with `docs/seniority-evidence.md` to connect the project to interview
   signal.

## Reviewer Takeaway

The project should be evaluated as evidence of Java design judgment: patterns
are useful only when they solve real change and maintenance pressure.
