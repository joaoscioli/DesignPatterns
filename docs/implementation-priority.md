# Implementation Priority

This file defines the next implementation order for turning the examples into a
stronger design-pattern portfolio.

## P1: Refactoring Examples

- Add before-and-after examples for one realistic business rule.
- Keep the first version intentionally simple.
- Introduce a pattern only when change pressure appears.

## P2: Test-Backed Design

- Add tests before refactoring.
- Show that behavior remains stable after the pattern is introduced.
- Document which tests prove the design improvement.

## P3: Pattern Comparison

- Compare the chosen pattern with simpler alternatives.
- Explain the maintenance cost of the abstraction.
- Add notes about when not to use the pattern.

## Why This Order

The repository becomes stronger when it proves judgment through change, not only
knowledge through definitions.
